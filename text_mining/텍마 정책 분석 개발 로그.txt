텍스트마이닝 기말 프로젝트 개발 기록 요약
작성 목적: 온통청년 청년정책 API 기반 소프로젝트의 개발 진행 과정, 오류 해결 과정, 분석 노트북 구성 내용을 간단히 정리하기 위함

1. 프로젝트 개요
본 프로젝트는 대학교 학부 텍스트마이닝 기말 프로젝트의 일부로 진행되었다.
전체 프로젝트 주제는 "채용공고 텍스트 기반 지역 청년 일자리 매력도 스코어링 분석: 서울·9개 도와 청년 유출 상위 지역을 중심으로"이다.
그중 본인은 팀장 역할을 맡았으며, 온통청년 청년정책 API를 활용해 지역별 청년정책 데이터를 수집하고, 정책명·정책설명·정책키워드를 분석하여 지역별 정책 공급 현황과 정책 키워드 대응도를 분석하는 소프로젝트를 수행하였다.

2. 초기 목표
초기 목표는 다음과 같았다.

- 온통청년 API에서 일자리 관련 청년정책 데이터를 수집한다.
- 서울 및 9개 도의 정책명, 정책설명, 정책키워드를 분석한다.
- 정책을 일자리, 직무교육, 주거지원, 창업지원, 복지, 참여 프로그램 등으로 분류한다.
- 채용공고 분석에서 드러나는 지역별 일자리 문제 유형과 정책 키워드가 얼마나 대응되는지 비교한다.
- 분석 결과를 바탕으로 지역별 청년정책 미스매치 또는 정책 대응 부족 분야를 파악한다.

3. 온통청년 API 수집 단계
처음에는 온통청년 API 호출 코드인 policy_scraper_planB.py를 작성하여 requests, pandas, xml.etree.ElementTree, tqdm 등을 활용하는 방식으로 데이터를 수집하려고 했다.
그러나 실행 과정에서 다음과 같은 문제가 발생하였다.

- API 요청 시 302 리다이렉트가 발생하였다.
- 일부 요청이 http://www.youthcenter.go.kr:8080/ 경로로 이동하였다.
- 현재 네트워크 환경에서 8080 포트 접속이 차단되어 ConnectTimeoutError가 반복되었다.
- 브라우저 주소창에 직접 API URL을 넣어도 응답이 없는 문제가 있었다.

이후 온통청년 API 이용 안내 HTML 파일을 분석한 결과, 기존 코드가 구버전 또는 문서와 맞지 않는 엔드포인트와 파라미터를 사용하고 있다는 점을 확인하였다.

기존 코드의 주요 문제는 다음과 같았다.

- /opi/youthPlcyList.do 경로를 사용하고 있었다.
- 인증키 파라미터로 openApiVlak을 사용하고 있었다.
- display, pageIndex, srchPolyBizSecd 등의 파라미터를 사용하고 있었다.
- 공식 문서 기준의 getPlcy API 구조와 맞지 않았다.

이를 개선하여 다음과 같은 방향으로 수정하였다.

- 공식 문서 기준 엔드포인트 /go/ythip/getPlcy 사용
- 인증키 파라미터 apiKeyNm 사용
- pageNum, pageSize, rtnType 등 공식 문서 기준 파라미터 사용
- JSON/XML 응답 모두 처리 가능하도록 개선
- 지역별 수집, 오류 로그 저장, raw 응답 저장 기능 추가
- API 키는 코드에 직접 넣기보다 환경변수 또는 실행 인자로 받을 수 있게 개선

4. 데이터 수집 결과
수정한 수집 코드를 실행한 결과, 온통청년 정책 자료를 요약한 CSV 파일 2개가 생성되었다.

- youth_policies_categorized.csv
- youth_policies_summary_by_region_category.csv

이후 youth_policies_categorized.csv를 기반으로 전처리, 스코어링, 텍스트마이닝 분석을 진행하였다.

초기에는 팀원들의 채용공고 분석 결과와 결합하는 구조로 3개의 Jupyter Notebook을 만들었다.

이 파일은 지역별 일자리취약도, 임금취약도, 워라밸취약도, 성장취약도 등을 담는 입력 파일이었다.

그러나 이후 프로젝트 방향을 수정하였다.

8. scikit-learn 버전 호환 문제 해결
3번 노트북을 실행하는 과정에서 다음 오류가 발생하였다.

AttributeError: 'TfidfVectorizer' object has no attribute 'get_feature_names_out'

오류 원인은 현재 Jupyter Notebook 환경의 scikit-learn 버전이 낮아서 최신 함수인 get_feature_names_out()을 지원하지 않기 때문이었다.
구버전에서는 get_feature_names()를 사용해야 한다.

이를 해결하기 위해 다음과 같은 호환 함수가 추가되었다.

def get_vectorizer_terms(vectorizer):
    if hasattr(vectorizer, "get_feature_names_out"):
        return np.array(vectorizer.get_feature_names_out())
    return np.array(vectorizer.get_feature_names())

이후 다음 코드들을 모두 수정하였다.

기존:
- region_terms = np.array(region_vectorizer.get_feature_names_out())
- cat_terms = np.array(cat_vectorizer.get_feature_names_out())
- cluster_terms = np.array(cluster_vectorizer.get_feature_names_out())

수정:
- region_terms = get_vectorizer_terms(region_vectorizer)
- cat_terms = get_vectorizer_terms(cat_vectorizer)
- cluster_terms = get_vectorizer_terms(cluster_vectorizer)

최종적으로 호환성 수정본은 다음 파일로 생성되었다.

- 03_policy_textmining_analysis_solo_ch1_7_compat.ipynb

9. 스코어링 가중치 확인
2번 노트북에서 "문제유형 가중치 합: 1.0"이라는 결과가 출력되었다.
이는 오류가 아니라 정상적인 결과이다.
가중치 합이 1.0이라는 것은 전체 문제유형의 중요도 비율이 100%로 맞춰졌다는 뜻이다.

예를 들어 고용기회, 임금소득, 직무성장, 워라밸환경, 주거안정, 창업생태계, 참여관계 등의 가중치를 모두 더했을 때 1.0이 되는 것이 정상이다.
이 값은 분석이 잘못되었다는 의미가 아니라, 가중치 설정이 정상적으로 이루어졌다는 의미이다.

11. 프로젝트에서 사용할 수 있는 주요 표현
보고서나 발표에서는 다음과 같이 표현하는 것이 적절하다.

"본 소프로젝트는 온통청년 API에서 수집한 청년정책 데이터를 기반으로 지역별 정책 공급 현황과 정책 키워드 대응도를 분석하였다. 정책명, 정책설명, 정책키워드, 정책지원내용을 결합하여 분석 텍스트를 구성하고, 정규표현식 기반 전처리와 불용어 처리를 수행하였다. 이후 일자리 문제 유형별 키워드 사전을 바탕으로 정책 대응도를 산출하고, 지역별 정책공급종합점수와 정책대응부족도를 계산하였다. 마지막으로 빈도 분석, TF-IDF, K-means 클러스터링 및 시각화를 통해 지역별 정책 텍스트의 특성을 분석하였다."

12. 주의할 점
- 현재 분석은 채용공고 원자료와 직접 결합한 분석은 아니다.
- 따라서 "채용공고 분석 결과와 직접 비교하였다"라고 쓰기보다는 "채용공고 분석에서 일반적으로 다루는 일자리 문제 유형을 기준으로 정책 키워드 대응도를 분석하였다"라고 쓰는 것이 더 정확하다.
- LDA 토픽모델링은 Chapter 1~7 교재 범위를 넘어가므로 최종 제출용에서는 제외하고, K-means 클러스터링을 사용하는 것이 더 안전하다.
- scikit-learn 구버전 환경에서는 get_feature_names_out() 오류가 발생할 수 있으므로 호환 함수가 들어간 3번 파일을 사용하는 것이 좋다.

초심자용 아주 간단한 단계별 요약

01_policy_preprocessing_solo.ipynb를 실행한다.
이 파일은 정책 데이터에서 빈칸을 정리하고, 중복을 확인하고, 분석할 텍스트를 깨끗하게 만든다.

3단계. 정책을 분류하기
정책을 일자리, 직무교육, 주거지원, 창업지원, 복지, 참여 프로그램 등으로 나눈다.

4단계. 스코어링하기
02_policy_scoring_keyword_fit_solo.ipynb를 실행한다.
이 파일은 지역별로 정책이 얼마나 충분한지 점수로 계산한다.
예를 들어 일자리 관련 정책이 많은지, 신청 URL이 있는지, 여러 분야의 정책이 골고루 있는지 등을 점수로 만든다.

5단계. 키워드 분석하기
03_policy_textmining_analysis_solo_ch1_7_compat.ipynb를 실행한다.
이 파일은 자주 나오는 단어, 지역별 중요한 단어, 분류별 중요한 단어를 찾는다.

6단계. TF-IDF 분석하기
단순히 많이 나온 단어가 아니라, 특정 지역이나 정책 분류에서 특히 중요한 단어를 찾는다.
이때 TF-IDF를 사용한다.

7단계. 클러스터링하기
비슷한 정책끼리 묶어 본다.
교재 Chapter 7에서 배운 K-means 클러스터링 방식에 맞춰 분석한다.

8단계. 그림으로 저장하기
분석 결과를 막대그래프 등으로 시각화한다.
보고서나 발표 자료에 넣을 수 있는 이미지 파일을 만든다.

9단계. 결과 해석하기
어떤 지역은 일자리 정책이 많고, 어떤 지역은 주거지원이나 창업지원이 부족한지 확인한다.
이를 바탕으로 지역별 정책 대응이 충분한지 또는 부족한지 설명한다.

10단계. 최종 보고서에 쓰기
"온통청년 정책 데이터의 텍스트를 전처리하고, 키워드 분석, TF-IDF, K-means 클러스터링을 통해 지역별 청년정책의 특징과 정책 대응 부족 분야를 분석하였다"라고 정리하면 된다.
