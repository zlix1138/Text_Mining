# 프로젝트 진행 중 발생한 오류 및 해결 과정 정리

이번 프로젝트를 진행하면서 온통청년 정책 데이터 수집, 전처리, 텍스트마이닝 분석, 청년 유출 데이터 결합, 정책 미스매치 분석까지 여러 단계를 수행하였다. 이 과정에서 API 요청 오류, 파일 경로 문제, CSV 인코딩 문제, 노트북 실행 오류, 컬럼명 불일치, 분석 기준 불일치 등의 문제가 발생하였다. 아래는 내가 실제로 겪은 주요 오류와 이를 어떻게 해결했는지 정리한 내용이다.

## 1. 온통청년 API 요청 오류

처음에는 온통청년 API를 이용해 청년정책 데이터를 수집하려고 하였다. 기존 코드에서는 `/opi/youthPlcyList.do` 주소와 `openApiVlak`, `display`, `pageIndex`, `srchPolyBizSecd` 등의 파라미터를 사용하고 있었다. 하지만 실행 결과 API 요청이 정상적으로 처리되지 않았고, `HTTPConnectionPool` 타임아웃 오류가 발생하였다.

이후 응답 상태를 확인해 보니 상태코드가 `302`로 나타났고, 요청이 `http://www.youthcenter.go.kr:8080/` 주소로 리다이렉트되고 있었다. 이로 인해 Colab 환경에서 8080 포트 접속이 되지 않아 타임아웃이 발생한 것으로 판단하였다.

해결을 위해 온통청년 API 안내 문서를 다시 확인했고, 기존 엔드포인트와 파라미터 구조가 문서 기준과 맞지 않는다는 점을 확인하였다. 이후 공식 문서 기준에 맞춰 `/go/ythip/getPlcy`, `apiKeyNm`, `pageNum`, `pageSize`, `rtnType` 등의 구조를 사용하는 방식으로 코드를 수정하였다. 또한 JSON/XML 응답을 모두 처리할 수 있도록 개선하고, 리다이렉트 발생 여부와 원본 응답을 저장하도록 코드를 보완하였다.

## 2. Colab 파일 경로 문제

Google Colab에서 코드를 실행하는 과정에서 내가 업로드한 파일이 보이지 않거나, 파일 경로를 잘못 지정하는 문제가 있었다. 특히 Colab의 `/content` 폴더 구조와 내 Windows PC의 로컬 경로가 다르기 때문에, 로컬에 있는 `Desktop/TM/tm` 경로를 Colab에서 직접 사용할 수 없었다.

이 문제는 Colab 왼쪽 파일 탭에 직접 파일을 업로드하거나, Google Drive를 마운트한 뒤 그 경로를 사용하는 방식으로 해결하였다. 이후 `!ls`, `!pwd`, `grep` 명령어를 사용해 현재 파일이 실제로 어느 위치에 있는지 확인하고, 코드에서 사용하는 경로를 그 위치에 맞게 수정하였다.

## 3. API 코드 파일 위치 착오

초기에 `policy_scraper_planB.py` 파일 위치를 정확히 확인하지 못해 잘못된 경로를 기준으로 설명하는 문제가 있었다. 이후 사용자가 직접 `grep` 명령어를 실행하여 파일 내부의 `API_URL` 위치와 요청 코드 위치를 확인하였다.

확인 결과 파일은 `/policy_scraper_planB.py` 위치에 있었고, API 요청은 `session.get(API_URL, params=params, headers=HEADERS, timeout=timeout)` 구조로 되어 있었다. 이 정보를 바탕으로 실제 코드 위치와 실행 위치를 다시 맞추었고, 이후 수정 방향을 정확히 잡을 수 있었다.

## 4. 중복 제거 결과가 0건으로 나온 문제

전처리 노트북을 실행했을 때 중복 제거 전후 데이터 수가 모두 5,470건으로 동일하게 나왔다. 처음에는 중복 제거가 제대로 작동하지 않은 것처럼 보였지만, 확인 결과 중복 판단 기준이 `지역 + 정책ID`였기 때문에 같은 지역 내에서 같은 정책ID가 반복된 경우만 제거하도록 되어 있었다.

온통청년 정책 데이터에서는 하나의 정책이 여러 지역에 등장할 수 있기 때문에, 정책ID만 기준으로 중복을 제거하면 지역별 분석에 필요한 정보가 사라질 수 있었다. 따라서 `지역 + 정책ID` 기준으로 중복을 유지한 것은 지역별 정책 분석 목적에는 적절하다고 판단하였다. 추가로 정책ID 기준, 정책명 기준, 지역+정책명 기준 등 여러 중복 진단 코드를 실행하여 데이터 구조를 확인하였다.

## 5. 정책 분류 기준 오류

초기 전처리 결과에서는 `정책중분류=창업`인 정책들이 `대표분류=일자리`로 분류되는 문제가 있었다. 이로 인해 창업지원 정책 수가 실제보다 매우 적게 나타났고, 일자리 정책 수가 과도하게 많아지는 문제가 있었다.

이를 해결하기 위해 공식 대분류와 중분류 정보를 함께 반영하는 방식으로 정책 분류 기준을 수정하였다. 기존에는 일자리 3,155건, 창업지원 18건으로 나왔지만, 개선 후에는 일자리 1,541건, 창업지원 765건 등으로 더 현실적인 분류 결과가 도출되었다. 이를 통해 정책 분야별 분포 해석의 왜곡을 줄일 수 있었다.

## 6. 분석 텍스트에 코드성 잡음이 포함된 문제

정책명, 정책설명, 정책키워드 등을 결합하여 분석 텍스트를 만들었을 때, `0043003`, `0011009`, `0 0`, `연령제한:N` 같은 코드성 값들이 텍스트에 포함되는 문제가 있었다. 이런 값들은 실제 정책 의미와 관련이 없기 때문에 키워드 분석이나 TF-IDF 분석의 품질을 떨어뜨릴 수 있었다.

이를 해결하기 위해 분석 텍스트 생성 과정에서 코드성 문자열, 불필요한 숫자 패턴, 반복 공백 등을 제거하는 정제 과정을 추가하였다. 또한 정책명, 정책설명, 정책키워드처럼 의미가 있는 컬럼을 중심으로 분석 텍스트를 구성하도록 수정하였다.

## 7. 날짜 파싱 문제

정책 신청 기간이나 운영 기간이 다양한 형식으로 입력되어 있어 단순한 날짜 파싱만으로는 처리하기 어려운 문제가 있었다. 예를 들어 `YYYYMMDD`, `YYYY-MM-DD`, `YYYY. M. D.`, `YYYY년 M월 D일`, `상시`, `연중`, `수시`, `예산소진시` 같은 값들이 혼재되어 있었다.

이 문제는 날짜 형식을 여러 패턴으로 처리하도록 개선하고, 명확한 날짜가 없는 경우에는 상시 여부나 신청 가능성 여부를 별도로 판단하는 방식으로 해결하였다. 이를 통해 신청 가능성 점수와 정보 접근성 점수 계산에 활용할 수 있도록 하였다.

## 8. job_region_scores.csv 파일 부재 문제

초기 스코어링 노트북에서는 `job_region_scores.csv` 파일이 필요하다는 메시지가 출력되었다. 이 파일은 원래 팀원의 채용공고 분석 결과와 정책 데이터를 연결하기 위한 입력 파일이었다. 하지만 당시에는 팀원 분석 결과와 직접 연계하지 않고, 온통청년 정책 데이터만으로 개인 소프로젝트 형태의 분석을 진행하기로 방향을 바꾸었다.

따라서 `job_region_scores.csv`를 강제로 만들기보다는, 정책 데이터 자체에서 지역별 정책 공급 점수와 정책 대응 부족도를 계산하는 구조로 노트북을 새로 설계하였다. 이후 `02_policy_scoring_keyword_fit_solo.ipynb`를 통해 정책 키워드 기반 문제유형 대응도와 정책공급종합점수를 산출하도록 수정하였다.

## 9. 교재 범위와 분석 기법 불일치 문제

처음 텍스트마이닝 분석 노트북에는 LDA 토픽모델링이 포함되어 있었다. 하지만 사용한 교재는 Chapter 1~7 범위였고, 그중 주요 내용은 전처리, 시각화, TF-IDF, K-means 클러스터링이었다. LDA 토픽모델링은 교재 범위를 넘어서는 분석으로 판단되었다.

이를 해결하기 위해 LDA 토픽모델링을 제외하고, 교재 Chapter 5의 TF-IDF 문서 표현과 Chapter 7의 K-means 클러스터링을 결합한 분석으로 수정하였다. 이후 보고서에서는 “토픽모델링”이라는 표현 대신 “TF-IDF 기반 K-means 정책 주제 유사 군집 분석”이라는 표현을 사용하기로 하였다.

## 10. scikit-learn 버전 호환 오류

3번 텍스트마이닝 노트북을 실행하는 과정에서 `TfidfVectorizer` 객체에 `get_feature_names_out()` 메서드가 없다는 오류가 발생하였다. 이는 scikit-learn 버전에 따라 메서드 이름이 다르기 때문에 발생한 문제였다.

최신 버전에서는 `get_feature_names_out()`을 사용하지만, 구버전에서는 `get_feature_names()`를 사용해야 한다. 이를 해결하기 위해 먼저 `get_feature_names_out()`을 시도하고, 오류가 발생하면 `get_feature_names()`를 사용하는 호환 함수를 추가하였다. 이후 지역별 TF-IDF, 분류별 TF-IDF, K-means 대표 키워드 추출 부분에 모두 적용하였다.

## 11. outputs 파일명에 `_solo`가 붙어 있는 문제

분석 결과 파일들이 모두 `policy_region_score_solo.csv`, `region_tfidf_keywords_solo.csv`처럼 `_solo`가 붙은 이름으로 저장되었다. 최종 보고서나 발표 자료에 사용하기에는 파일명이 다소 길고 정리되지 않은 느낌이 있었다.

이를 해결하기 위해 `outputs` 폴더 안의 파일명에서 `_solo`를 제거하는 코드를 작성하였다. 이 코드는 `outputs` 폴더와 같은 위치의 프로젝트 루트 폴더에서 실행하도록 하였고, 파일명 중복이 발생할 경우 기존 파일을 덮어쓰지 않도록 처리하였다. 이후 정리 코드도 `_solo`가 제거된 파일명 기준으로 수정하였다.

## 12. final_analysis_results 폴더명을 final_results로 바꾼 문제

처음 결과 정리 코드에서는 최종 결과 폴더명이 `final_analysis_results`로 설정되어 있었다. 하지만 프로젝트 폴더 구조를 더 간단히 정리하기 위해 `final_results`라는 이름을 사용하기로 했다.

이 문제는 코드 상단의 `RESULT_DIR = Path("final_analysis_results")` 부분을 `RESULT_DIR = Path("final_results")`로 수정하여 해결하였다. 이후 모든 하위 폴더와 README 파일이 `final_results` 안에 생성되도록 정리하였다.

## 13. TF-IDF 결과 폴더가 비어 있던 문제

`final_results/04_region_tfidf_keywords` 폴더가 생성되었지만 내부 파일이 비어 있는 문제가 있었다. 확인 결과 `region_tfidf_keywords.csv` 파일의 실제 컬럼명은 `['지역', '순위', '키워드', 'TFIDF']`였는데, 기존 코드에서는 TF-IDF 점수 컬럼 후보에 `TFIDF`가 포함되어 있지 않았다.

기존 코드는 `tfidf`, `TF-IDF`, `tfidf_score`, `점수`, `score` 등만 찾고 있었기 때문에 실제 컬럼명을 인식하지 못했다. 이를 해결하기 위해 후보 목록에 `TFIDF`를 추가하였고, 이후 4번 지역별 TF-IDF 핵심 키워드 정리 파일이 정상적으로 생성되었다.

## 14. K-means 클러스터 컬럼명 오류

K-means 결과 정리 과정에서 `KeyError`가 발생하였다. 기존 코드는 클러스터 컬럼명을 `cluster`, `클러스터`, `군집`, `Cluster` 중에서 찾도록 되어 있었다. 하지만 실제 `kmeans_cluster_size.csv` 파일의 컬럼명은 `KMeans클러스터`와 `정책수`였다.

따라서 코드가 클러스터 컬럼을 찾지 못하고 오류를 발생시킨 것이다. 이를 해결하기 위해 클러스터 컬럼 후보 목록에 `KMeans클러스터`, `KMeans군집`, `kmeans_cluster`, `KMeansCluster` 등을 추가하였다. 이후 K-means 클러스터별 정책 수, 대표 키워드, 대표 정책 예시 파일이 정상적으로 정리되었다.

## 15. 청년순이동률 계산 불가 문제

처음 업로드한 청년 이동 자료는 시군구·성·연령 5세별 순이동자수 자료였다. 이 파일에는 청년층(19~34세) 순이동자수는 포함되어 있었지만, 청년순이동률을 계산하기 위한 분모인 청년연앙인구가 포함되어 있지 않았다.

처음에는 이 파일만으로 청년순이동률을 계산할 수 있을지 검토했지만, 공식적인 순이동률은 `순이동자수 ÷ 주민등록연앙인구 × 100` 구조이므로 순이동자수만으로는 계산할 수 없다고 판단하였다. 이후 청년연앙인구 자료를 추가로 확보하여 문제를 해결하였다.

## 16. 연앙인구 자료의 연령 구간 문제

추가로 확보한 주민등록연앙인구 자료는 5세 단위 연령 구간으로 제공되었다. 하지만 대한민국 청년 기준은 일반적으로 19~34세이고, 5세 단위 자료에는 15~19세, 20~24세, 25~29세, 30~34세처럼 구간이 나뉘어 있었다. 따라서 19세만 정확히 분리할 수 없는 문제가 있었다.

이를 해결하기 위해 15~19세 인구 중 19세에 해당하는 값을 1/5로 근사하였다. 최종 청년연앙인구는 다음 식으로 계산하였다.

청년연앙인구 = 15~19세 인구의 1/5 + 20~24세 인구 + 25~29세 인구 + 30~34세 인구

이 방식은 완전히 정확한 1세 단위 계산은 아니지만, 5세 단위 자료를 사용하는 상황에서 19~34세 기준을 최대한 맞추기 위한 합리적인 근사로 판단하였다. 보고서에는 이 내용을 한계점으로 명시하기로 하였다.

## 17. 순이동자수 기간과 연앙인구 기준연도 불일치 문제

순이동자수 자료는 2025년 11월부터 2026년 4월까지의 월별 자료였고, 연앙인구는 2025년 기준 자료를 사용하였다. 따라서 최종 계산된 청년순이동률은 엄밀한 의미의 연간 순이동률이 아니라, 분석기간 기준 순이동률이었다.

이를 해결하기 위해 결과 해석에서 “2025.11~2026.04 기간의 청년 순이동자수 합계를 2025년 청년연앙인구로 나누어 계산한 분석기간 기준 청년순이동률”이라고 명시하였다. 즉, 연간 공식 지표처럼 과장하지 않고 분석 기준을 분명히 적는 방식으로 처리하였다.

## 18. youth_migration.csv 생성 과정 정리 필요

청년순이동자수와 청년연앙인구를 결합해 `youth_migration.csv`를 만들었지만, 이 파일이 어떻게 만들어졌는지 설명할 문서가 필요했다. 특히 보고서나 팀원 공유 과정에서 어떤 기준으로 계산했는지 명확히 설명해야 했다.

이를 해결하기 위해 `youth_migration.csv` 제작 과정 요약 TXT 파일을 따로 생성하였다. 이 파일에는 사용 자료, 청년 기준, 순이동자수 처리 방식, 연앙인구 처리 방식, 지역명 정리, 청년순이동률 계산식, 한계점 등을 정리하였다.

## 19. 정책 데이터만으로 미스매치 분석을 완료했다고 볼 수 없는 문제

초기에는 온통청년 정책 데이터와 final_results만으로 정책 미스매치 분석을 수행했다고 볼 수 있을지 검토하였다. 하지만 객관적으로 보면 정책 데이터만으로는 청년 유출 문제와 정책 대응 간의 미스매치를 직접 검증했다고 보기 어려웠다.

정책 미스매치는 청년 유출 위험이 큰 지역과 정책 대응이 부족한 지역이 겹치는지를 확인해야 하므로, 청년 유출 데이터가 반드시 필요했다. 이를 해결하기 위해 `youth_migration.csv`를 생성하고, 기존 정책공급종합점수 및 정책대응부족도와 병합하는 방식으로 분석 구조를 보완하였다.

## 20. 미스매치 분석 노트북 이름 수정

처음에는 새 노트북 이름을 `05_youth_outflow_policy_mismatch.ipynb`로 제안했지만, 이후 프로젝트 파일명 통일성을 위해 `05_youth_policy_mismatch.ipynb`로 수정하였다. 이후 모든 설명과 실행 계획에서 이 이름을 기준으로 사용하였다.

## 21. 미스매치 점수 계산 방식 설정 문제

청년 유출 데이터와 정책 데이터가 준비된 뒤, 두 데이터를 어떻게 결합할지에 대한 기준이 필요했다. 단순히 청년순이동률과 정책대응부족도를 나란히 보여주는 것만으로는 미스매치 정도를 명확히 비교하기 어려웠다.

이를 해결하기 위해 청년순이동률이 낮을수록 높아지는 `청년유출위험도`를 만들고, 이를 0~100점으로 정규화하였다. 이후 정책대응부족도와 결합하여 다음 식으로 정책미스매치점수를 계산하였다.

정책미스매치점수 = 청년유출위험도 × 정책대응부족도 ÷ 100

이 방식은 청년 유출 위험과 정책 대응 부족이 동시에 높을 때만 점수가 크게 나오기 때문에, 미스매치 판단에 적합하다고 보았다.

## 22. 토픽모델링 표현 문제

미스매치 지역 정책 텍스트를 추가 분석하는 과정에서 토픽모델링을 사용할지 검토하였다. 그러나 LDA 기반 토픽모델링은 교재 범위를 넘어설 수 있었기 때문에, 수업 범위에 맞추려면 사용하지 않는 것이 안전하다고 판단하였다.

이를 해결하기 위해 LDA 대신 TF-IDF 기반 K-means 클러스터링을 사용하고, 이를 “정책 주제 유사 군집 분석”으로 설명하였다. 이 방식은 교재의 TF-IDF와 K-means 클러스터링 범위에 포함되므로, 분석 방법을 수업 내용과 더 잘 연결할 수 있었다.

## 23. 최종 결과 요약본 생성 필요

정책 데이터 분석 결과, 청년 유출 데이터 분석 결과, 정책 미스매치 분석 결과가 각각 다른 폴더와 파일에 나뉘어 저장되어 있어, 팀원들에게 바로 공유하기에는 복잡했다.

이를 해결하기 위해 `final_results`와 `final_mismatch_results`를 종합하여 팀원 보고용 TXT 요약본을 생성하였다. 이 요약본에는 전체 진행 요약, 사용 데이터, 전처리 기준, 정책 데이터 분석 결과, 청년 유출 데이터 분석 결과, 스코어링 방식, 정책 미스매치 결과, 4분면 분석, 텍스트마이닝 분석, 발표용 1분 요약문, 한계점 등을 포함하였다.

## 최종 정리

이번 프로젝트에서 발생한 오류들은 단순한 코드 오류뿐만 아니라, 데이터 기준과 분석 목적이 맞지 않아 생긴 문제도 많았다. API 요청 오류, 파일 경로 문제, 컬럼명 불일치, 인코딩 문제, 교재 범위 초과, 청년순이동률 계산 기준 문제 등이 대표적이었다.

각 문제는 다음 방식으로 해결하였다.

* API 오류는 공식 문서 기준으로 엔드포인트와 파라미터를 수정하여 해결하였다.
* 파일 경로 문제는 현재 작업 폴더와 파일 위치를 확인하고, 프로젝트 루트 기준으로 경로를 통일하여 해결하였다.
* 컬럼명 불일치 문제는 실제 CSV 컬럼명을 확인한 뒤 후보 컬럼 목록을 보완하여 해결하였다.
* scikit-learn 버전 문제는 `get_feature_names_out()`과 `get_feature_names()`를 모두 지원하는 호환 코드로 해결하였다.
* 청년순이동률 계산 문제는 연앙인구 자료를 추가 확보하여 해결하였다.
* 5세 단위 연령 구간 문제는 15~19세의 1/5을 19세로 근사하여 해결하였다.
* 교재 범위 초과 문제는 LDA 토픽모델링 대신 TF-IDF 기반 K-means 정책 주제 유사 군집 분석으로 대체하여 해결하였다.

결과적으로 처음에는 정책 데이터 중심 분석에 머물렀지만, 이후 청년 유출 데이터와 정책대응부족도 결과를 결합하여 청년 유출-정책 미스매치 분석까지 확장할 수 있었다.
